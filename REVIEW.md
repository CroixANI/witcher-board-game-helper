# REVIEW.md — правила code review

Применяются к review субагентом `code-reviewer` (из `/next-task`) и к ручному review PR.

## Severity
- **Important** — сломает поведение, расходится с правилами игры или SPEC, нарушает правовые правила проекта, оставляет новое поведение без тестов или ослабляет существующие тесты. Исправляется до PR.
- **Nit** — всё остальное: стиль, имена, мелкие улучшения. Максимум **5** в отчёте, остальные — числом. Автоматически не исправляются, решает пользователь.

Каждая находка ссылается на `path:line`. Нет ссылки — нет находки.

## Проходы (каждая находка помечена)
1. **Bugs** — поведение, пограничные случаи, состояние wizard'а («Назад», сброс, восстановление из `localStorage`), обработка ошибок, доступность, безопасность HTML.
2. **Rules** — соответствие книге правил (пересказ, страницы) и решениям SPEC D1–D9.
3. **Compliance** — соответствие задаче из ROADMAP («Готово, когда», затронутые файлы, без scope creep), правилам `CLAUDE.md`, покрытию тестами.

## Всегда проверять
- У каждого нового узла wizard'а, карточки правил и FAQ-записи из книги есть страница. Утверждение совпадает с книгой.
- Нет изображений из книги правил, карт или поля и нет внешних ссылок на PDF правил (D4, D5).
- Соло нигде не появляется; число игроков — 2–5 (D3).
- Внутренние ссылки строятся через `url()` или `BASE_URL`, без жёсткого `/…` (base path GitHub Pages).
- Все обращения к `localStorage` идут через `safeStorage`.
- Новое поведение покрыто тестами: unit для логики, e2e для пользовательских сценариев (с M2).
- `src/lib/wizard-engine.ts` не зависит от UI.

## Не сообщать
- Форматирование, которое правят Prettier и ESLint.
- Предпочтения без объективной пользы («я бы назвал иначе»).
- Предложения за рамками задачи. Их можно упомянуть одной строкой как «вне scope».
