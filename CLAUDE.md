# CLAUDE.md — witcher-board-game-helper

Фанатский помощник для настольной игры «Ведьмак: Старый мир» (базовая игра, 2–5 игроков). Это статический mobile-first сайт на Astro + Preact, хостинг — GitHub Pages: https://croixani.github.io/witcher-board-game-helper/

Язык проекта — **русский** (документы, контент, PR, коммит-сообщения после префикса). Общепринятые английские термины и идентификаторы в коде допустимы. Пользователь — разработчик (CI/CD, GitHub, `gh`), базовые вещи не объяснять.

## Как работает сессия
- **Одна сессия = одна задача из `docs/ROADMAP.md` = одна ветка = один PR.**
- Стандартный запуск: `/next-task` (skill `.claude/skills/next-task/SKILL.md`). Это весь процесс: выбор задачи, реализация, тесты, упрощение и code review свежими субагентами, PR, статус в ROADMAP. Если пользователь сформулировал просьбу иначе («сделай следующую задачу»), всё равно следуйте этому skill.
- Комментарии в PR и упавший CI разбирает `/pr-sweep <N>`.
- Субагенты: `.claude/agents/simplifier.md` (упрощает без изменения поведения), `.claude/agents/code-reviewer.md` (только читает). Правила review — `REVIEW.md`.
- **Никогда не пушить в `main` и не мержить PR.** PR мержит пользователь вручную после зелёного CI.
- Задача не завершена, пока не выполнены её критерии «Готово, когда» и общий DoD из ROADMAP.

## Источники правды (по убыванию приоритета)
1. **Книга правил** `Vedmak_Stary_Mir__pravila_RUS.pdf` (36 стр.). Если SPEC или код расходятся с правилами — правы правила; расхождение исправить и упомянуть в PR.
2. `docs/SPEC.md` — спецификация. Решения D1–D9 в разделе 1.1 главнее брифа.
3. `docs/ROADMAP.md` — задачи и их статусы.
4. `docs/PLAN.md` — исходный бриф (история; устаревшие места перекрыты SPEC).

**Где взять PDF правил:** в git его нет (чужой копирайт, `.gitignore`). Ищите в таком порядке:
- `docs/Vedmak_Stary_Mir__pravila_RUS.pdf` в локальной папке пользователя;
- файл проекта claude.ai «Ведьмак - Старый Мир» (приходит вложением в сессию);
- если PDF нет, а задача контентная — попросите пользователя приложить его. Пересказ правил по памяти недопустим.

Текст извлекается так: `pdftotext -f N -l N <pdf> -`. Страницы с картинками смотрите через `pdftoppm -r 70 -png -f N -l N`.

## Жёсткие правила контента
- Только **своими словами**: не копировать тексты книги правил, карт и официального FAQ.
- У каждого шага wizard'а, карточки правил и FAQ-записи из книги — **номер страницы**.
- **Никаких изображений из книги правил, карт или поля** — только собственные SVG (SPEC, раздел 11). Никаких внешних ссылок на PDF правил (SPEC D5).
- Соло-режим исключён (D3). Число игроков — 2–5.
- Лимит руки — по книге: при 7 картах новые не берутся (D6).

## Тесты — обязательны
- **Кодовая задача без новых или обновлённых тестов не считается выполненной.** Новое поведение покрывается unit-тестами (Vitest), UI-сценарии — Playwright (с M2).
- **Контентные задачи** покрываются валидацией схем и граф-тестами (`npm test` включает `validate:content`).
- Перед PR локально должны пройти: `npm run lint && npm run check && npm test && npm run build` (+ `npm run test:e2e`, когда он появится).
- Тесты гоняет CI на каждом PR. Merge возможен только при зелёном CI (защита ветки `main`).

## Git и GitHub
- Ветки: `<type>/<task-id>-<slug>`, например `feat/r2.1-wizard-engine`. Типы: `feat`, `fix`, `content`, `chore`, `test`, `perf`, `docs`.
- Коммиты — Conventional Commits: `feat: …`, `content: …`, `chore: …`.
- Репозиторий: `CroixANI/witcher-board-game-helper`, слияние — только squash.
- **GitHub API — только REST.** В облачных сессиях GraphQL закрыт, поэтому `gh pr create`, `gh pr list`, `gh pr checks`, `gh pr view` падают. Используйте скрипты `scripts/session/*.sh` (внутри `gh api` REST) — они работают и локально, и в облаке.
- Настройки репозитория (Pages, защита веток) из облачной сессии недоступны (403 от прокси). Нужна такая настройка — дайте пользователю готовую команду `gh`.

## Структура
