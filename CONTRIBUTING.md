# Как участвовать

## Процесс
- **1 задача = 1 ветка = 1 PR.** Задачи — в [`docs/ROADMAP.md`](docs/ROADMAP.md), в описании PR укажите `Задача: R?.?`.
- Ветка `main` защищена: только через PR с зелёным CI, слияние — squash.
- Имена веток: `<type>/<id>-<slug>`, например `feat/r2.1-wizard-engine`, `content/r1.4-rules-part1`, `fix/…`, `chore/…`, `test/…`.
- Коммиты — [Conventional Commits](https://www.conventionalcommits.org/): `feat:`, `fix:`, `content:`, `chore:`, `test:`, `docs:`.
- Перед PR: `npm run lint && npm run check && npm test && npm run build`.

## Правила для контента
- **Только своими словами.** Не копируйте тексты книги правил, карт и официального FAQ — пересказывайте.
- **Всегда указывайте страницу** книги правил (`page` / `pages`). Сверяйте с книгой, а не с памятью или пересказом.
- **Никаких изображений из книги правил, карт или поля.** Только собственные SVG (см. SPEC, раздел 11).
- **Ссылка на место на поле** — обычная Markdown-ссылка со схемой `zone:` и id зоны: `[ряд карт](zone:z-action-row)`, `[дальняя ячейка](zone:z-action-row-minus1)`. Список id — `src/data/board-zones.ts` (тексты зон — `src/content/zones/`). Только inline-форма: `[r]: zone:…` не поддерживается. Работает только в теле `.md` (правила, шаги подготовки, «не мой ход», FAQ), в YAML — нет. Неизвестный id ломает `npm test` и сборку.
- Книга правил главнее SPEC и брифа. Нашли расхождение — issue «Ошибка в правилах / wizard'е».

## Как добавить вопрос
Один вопрос = один файл `src/content/faq/<slug>.md`. На сайте он появляется в списке `/faq/` (в группе своей фазы, с якорем `#<slug>`) и на отдельной странице `/faq/<slug>/`.

**Путь 1 — есть доступ к репозиторию (≈ 1 клик):**
1. GitHub → `src/content/faq/` → откройте `_template.md`, скопируйте текст.
2. *Add file → Create new file* → имя `<slug>.md` (`slug` — латиницей через дефис, например `meditation-last-trophy`).
3. Заполните frontmatter:
   - `question` — вопрос, заканчивается на `?`;
   - `tags` — 1–3 тега;
   - `phase` — `setup` | `phase1` | `phase2` | `battle` | `phase3` | `general` (группа в списке);
   - `source` — `rulebook` (тогда обязателен `page`) | `official-faq` (+ `sourceRef`: «Офиц. FAQ, Базовая игра, п. N») | `house` (договорённость стола);
   - `rules` — id связанных карточек правил (имена файлов в `src/content/rules/` без `.md`);
   - `zones` — необязательно: id зон поля из `src/data/board-zones.ts`. Под ответом появится «Показать на поле», а на `/board/` в карточке зоны — ссылка на вопрос в блоке «Частые вопросы здесь»;
   - `updated` — дата.
4. Ответ — до 120 слов, своими словами, со ссылкой «(стр. N)». Можно ссылаться на место на поле: `[ряд карт](zone:z-action-row)`.
5. *Commit to a new branch* → *Create pull request*. Прямой push в `main` закрыт. CI проверит схему (неизвестная зона, правило или пропущенная страница — ошибка), после merge сайт обновится.

**Путь 2 — доступа нет:** создайте issue по форме **«Новый вопрос в FAQ»** (label `faq`). Владелец оформит файл по шаблону и в PR напишет `Closes #N`.

Файл `_template.md` в коллекцию не попадает и на сайте не виден.

## Сообщить об ошибке в правилах
Issue по форме **«Ошибка в правилах / wizard'е»**: где (URL или шаг wizard'а), что написано, как по правилам, страница книги.
